# final / static / static final 은 각각 어떤 역할을 하며, 차이는 무엇인가요?
## static
객체 생성 없이 사용할 수 있는 필드와 메소드를 생성할 때 활용한다.
예를 들어 우리는 `Sopt server = new Sopt()` 처럼 귀찮에 인스턴스를 만들었었다... 하지만 static을 사용한다면?
`Sopt.hi()`처럼 "클래스이름.필드"로 사용할 수 있다
하지만 참조 변수로 이용하는 걸 추천되지 않는다
정적 메소드는 객체 참조 없이 바로 사용할 수 있다고 했었다.
그렇기에 인스턴스 필드나 메소드 그리고 this 키워드를 사용할 수 없게된다.
생각해보면 당연하다 인스턴스 성질은 객체 생성 후 사용할 수 있기 때문

## final
값이 저장 -> 최종 값 따라서 수정이 불가능하다
우리는 Spring Boot를 하게 되면 이 final을 굉장히 그리고 자주 마주 하게 된다
어떤 값이 변하지 않고 싶을 때 예를 들어 가게 문 열고 닫는 시간 같은 경우 나머지는 변경되어도
"이건 고정해야해!"할 때 사용

## static final
"고정된" + "최종적인" 의 의미로, 상수를 선언할 때 사용
다시 요약해보자,
- `static`: 객체마다 생성되는 것이 아니라 클래스에 하나만 존재하며 공유된다.
- `final`: 한 번 값이 할당되면 다른 값으로 다시 할당할 수 없다.

final로 상수로 만족될 것 같지만 final만 있으면 상수를 의미할 수 없다 그 이유는
`final`만 사용하면 객체마다 각각 다른 값을 가질 수 있기 때문에 보통 클래스 전체에서 하나의 고정된 값을 공유하는 상수는 `static final`로 선언한다.


즉, 모든 영역에서 고정된 값으로 사용하는 상수를 의미한다.

# Java의 Generic 타입은 무엇이며 왜 사용할까요?
데이터 형식에 의존하지 않고, 하나의 값이 여러 다른 데이터 타입을 가질 수 있도록 하는 방법이다
## 예시
`객체<타입> 객체명 = new 객체<타입>();` 
우리는 위의 코드처럼 주로 사용한다. 이 과제에서는 공통 응답 객체를 만들 때 사용하였다.
## 사용 이유
제네릭은 클래스 내부에서 짖어하는 것이 아닌 외부에서 사용자에 의해 지정된다 한마디로 특정 타입을 미리
지정해주는 것이 아닌 필요에 의해 지정할 수 있도록 하는 일반 타입으로 코드를 짤 때 수월해진다.

## 장점
1. 제네릭을 사용하면 잘못된 타입이 들어올 수 있는 것을 컴파일 단계에서 방지할 수 있다.
2. 클래스 외부에서 타입을 지정해주기 때문에 따로 타입을 체크하고 변환해줄 필요가 없다. 즉, 관리하기 편하다
3. 비슷한 기능을 지원하는 경우 코드의 재사용성이 높아진다

## 단점
1. 제네릭을 처음 마주하는 경우 어려움
2. 상속 및 구현하는 과정에서 계층 구조가 복잡하다면 어려워진다

## 타입 예시
<T> -> Type
<E> -> Element
<K> -> Key
<V> -> Value
<N> -> Number



# primitive type vs wrapper class 차이는 무엇이며 어떤 상황에서 무엇을 사용해야 할까요?
기본형과 래퍼 클래스로 아래에서 정의함

## 기본형: 계산을 위한 실제 값을 저장한다
- 논리, 문자, 정수, 실수를 포함

## 래퍼 클래스
- 기본형 데이터 타입을 객체로 변환한 클래스
- 래퍼 클래스를 사용한다면 기본형 값을 객체로 다룰 수 있음
- 객체 생성 시, 기본형 데이터 타입을 저장하는 필드가 존재

## 래퍼 클래스 사용 이유
1. 기본형 데이터 타입을 객체로 변환할 수 있다
   - 즉, 기본형 타입을 객체로 만들어 null을 넣거나 메서드를 사용할 수 있음
2. java.util 패키지의 클래스는 객체만 처리하므로 래퍼 클래스가 필요
3. Collection Framework의 데이터 구조는 기본타입이 아닌 객체만 저장한다
   - 아까말한 제네릭 타입은 기본형 x
4. 멀티 쓰레딩과 동기화를 지원하려면 객체가 필욯다ㅏ

# 여러분이 선택한 아키텍처의 각 요소 또는 계층은 어떤 역할과 책임을 가지는지 구체적으로 설명해주세요.
## Controller

Controller는 사용자의 요청을 가장 먼저 받고, 그 요청을 어떤 서비스로 넘길지 결정하며, 최종적으로 어떤 응답 형식으로 반환할지 정리하는 계층
현재 코드에서는 `PostController`가 이 역할을 하고 있다. 또한 예외가 발생했을 때 실패 응답 메시지로 바꾸는 책임도 일부 존재

## Service
Service는 실제 비즈니스 로직을 처리하는 계층
게시글을 조회할지, 수정할지, 삭제할지, 어떤 검증을 거쳐야 하는지 같은 처리 흐름이 여기에 들어간다.
현재 코드에서는 `PostService`가 게시글 목록을 관리하고, 검증기(`PostValidator`)를 호출하고
=> 게시글을 찾고 수정/삭제하는 역할을 맡고 있다.

## Repository
Repository는 데이터를 저장하고 꺼내는 역할을 맡는 계층
보통 데이터베이스와 가장 가까운 계층이라고 생각하는데 나중에 JPA를 배운다면 인터페이스 확장한다. 
현재 코드에는 `PostRepository`가 정의되어 있고, 저장, 전체 조회, 단건 조회, 삭제 기능을 메서드로 갖고 있다.
수정하는 부분은 게시글 상태 자체를 저장한다고 보기에 Domain/Post.java에 있다

## Domain

Domain은 서비스가 다루는 핵심 데이터 자체를 표현하는 계층
현재 코드에서 `Post`는 게시글 하나를 표현하는 도메인 객체입니다. 
게시글이 가져야 하는 속성(`id`, `title`, `content`, `author`,`enum`, `createdAt`)과 `updata` 가 존재한다

## 정리
- Controller: 요청/응답 처리
- Service: 비즈니스 로직 처리
- Repository: 데이터 저장소 접근
- Domain: 핵심 데이터와 상태 표현

이렇게 역할을 나누면 코드 책임이 분명해지고, 수정이나 확장이 쉬워진다.
